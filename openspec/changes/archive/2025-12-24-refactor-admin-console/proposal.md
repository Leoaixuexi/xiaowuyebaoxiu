# Change: 重构管理员后台系统

## Why

当前管理员功能分散在多个页面，缺乏统一入口和完整的管理能力。管理员无法高效完成账号管理、公告发布、消息模板配置等核心运营工作。需要重构管理员后台，提供统一入口和完整的管理功能。

## What Changes

### P0 核心功能（本次实现）

1. **管理台首页** - 统一管理入口
   - 管理员登录后默认进入管理台（不进入工单工作台）
   - 卡片式入口：账号管理、角色与权限、系统配置、公告管理、消息模板、审计日志

2. **账号管理增强** - 增强现有用户管理功能
   - 用户列表增加筛选（角色、部门、启用状态、关键字）
   - 新增/编辑用户完整表单
   - 启用/停用账号功能
   - 重置密码功能
   - 约束：禁止管理员降级/禁用自己

3. **公告管理** - 全新功能
   - 公告CRUD：标题、内容、发布/下线、有效期
   - 可见范围：按角色多选
   - 普通用户在"消息/通知公告"中查看

4. **消息模板管理** - 全新功能
   - 按场景维护模板（工单状态更新、提醒处理等）
   - 模板字段：标题、正文、变量占位、启用/停用
   - 仅管理员可编辑

### P1 功能（后续迭代）
- 角色与权限：页面/按钮级权限配置
- 系统配置：SLA规则、故障类型管理
- 审计日志：增强筛选和导出

### P2 功能（可选）
- 系统工具：迁移/修复/诊断工具

## Impact

### 数据源决策
- **统一使用云函数/云数据库**（保持与现有架构一致）
- 新增云数据库集合：announcements、message_templates
- 权限校验在云端强制执行（不仅靠前端隐藏）

### Affected Specs
- `admin-dashboard` - 新增管理台首页能力
- `user-management` - 增强现有用户管理能力
- `announcement-management` - 新增公告管理能力
- `message-template` - 新增消息模板能力

### Affected Code
- `pages/admin/` - 管理页面目录
- `services/cloudDatabase.js` - 云数据库服务扩展
- `cloudfunctions/` - 云函数扩展
- `utils/constants.js` - 常量扩展
- `app.js` - 管理员登录跳转逻辑

### Breaking Changes
- **BREAKING**: 管理员角色(role_id=1)登录后默认跳转管理台，而非工单工作台
